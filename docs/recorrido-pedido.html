Así viaja un pedido por voz

Guía visual del recorrido entre navegador, STT, LLM configurado, reglas de negocio y carrito. Cada tarjeta identifica el archivo y la función que participa.

1. Encender el proyecto

Desde la raíz del repositorio, el siguiente comando inicia FastAPI. La aplicación carga el menú, sirve el frontend y queda a la espera de sesiones.

.\.venv\Scripts\Activate.ps1
python -m uvicorn backend.api.app:app --reload

Luego se abre http://127.0.0.1:8000.

Capas: Frontend / navegador API / transporte Voz e IA Dominio y reglas

2. Diagrama de flujo: pedido hablado

Ejemplo: la persona dice «Hola, quiero una hamburguesa clásica con Coca-Cola y tomate». Las tarjetas se presentan en una sola columna para que cada flecha una exclusivamente un paso con el siguiente: 1 ↓ 2 ↓ 3.

1. Arranque de FastAPI

backend/api/app.py menu = load_menu(MENU_PATH) carga config/menu.json; FastAPI sirve frontend/.

2. Pantalla y sesión

frontend/app.js createSession() ejecuta fetch("/api/sessions", { method: "POST" }). Con el session_id recibido, connectWebSocket(), en este mismo archivo, abre ws://.../ws/sessions/{session_id}.

3. Backend crea el pedido vacío

backend/api/app.py La ruta @app.post("/api/sessions") ejecuta create_session(), que ensambla Session, OrderService y el OrderInterpreter elegido por LLM_PROVIDER (Groq en la demo). La ruta WebSocket de este archivo recibe después la conexión abierta en el paso 2.

4. La persona toca Hablar

frontend/app.js toggleMicrophone() envía audio.start; VoiceInput prepara el micrófono.

5. Audio del micrófono

frontend/voice.js y pcm-worklet.js Convierten la captura a PCM16 mono de 16 kHz. sendAudio() manda fragmentos binarios por WebSocket.

6. STT: voz a texto

backend/ai/live_transcriber.py SpeechToText / GeminiLiveTranscriber.transcribe() usa el modelo indicado en GEMINI_TRANSCRIPTION_MODEL, publica hipótesis y devuelve el texto final.

7. El texto entra al mismo flujo que escritura

conversation_socket.py process_turn() recibe el texto final; execute() llama al intérprete LLM sin bloquear el WebSocket.

8. El LLM interpreta la intención

orchestrator.py send_message() conversa con el proveedor elegido por LLM_PROVIDER (Groq en la demo). El LLM propone una tool, no modifica el carrito por sí mismo.

9. Tool autorizada

backend/ai/tools.py create_add_item_tool() crea add_item(), revisa grupos obligatorios y delega la operación segura.

10. Reglas y precio

backend/services/order_service.py OrderService.add_item() y _calculate_unit_price() validan catálogo, disponibilidad y precio.

11. Carrito validado

Cart, CartItem y Menu Se guarda una línea con producto, bebida, extra y precio. El carrito es el estado real del pedido.

12. Pantalla actualizada

frontend/app.js onServerMessage() recibe cart.updated; applyCart() y renderCart() muestran el resultado.

3. Conversación completa: agregar, consultar, modificar, eliminar y pagar

Una misma sesión puede recibir varios turnos. Este ejemplo muestra el recorrido esperado de cada operación.

Las tools indicadas son las operaciones que el LLM configurado puede proponer. OrderService decide si son válidas; una pregunta de precio no debe crear una línea provisional en el carrito.

Si luego se agregan tres unidades con el mismo producto, bebida y extras que una línea existente, OrderService.add_item() las consolida: el carrito muestra una sola línea con cantidad cuatro. Si la persona dice «eliminá una», el intérprete debe proponer adjust_quantity(delta=-1) y quedan tres; remove_item() se reserva para eliminar la línea completa.

Lo que el LLM puede y no puede hacer

El LLM configurado interpreta lenguaje natural y puede proponer una tool. No decide precios, stock ni modifica el carrito directamente.

La autoridad final es OrderService. Por eso la misma regla protege voz, texto y botones del frontend.

Si falta información

Si la persona dijera solo «quiero una Burger Clásica», add_item() no agrega una línea incompleta: devuelve que falta el grupo obligatorio Bebida.

Límite actual de la demo: la transcripción, el LLM configurado y la sesión viven en un proceso local. Si un proveedor falla, el carrito ya validado se conserva. Si se reinicia el backend, las sesiones en memoria se pierden.
